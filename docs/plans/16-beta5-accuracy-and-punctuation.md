`engine_info.punctuation` is replaced wholesale on every build (post-pass, import, Restore, rebuild); Restore's `engine_info` clone (restore.rs 182) must not carry an old block over.

Unit of work: per channel, the words in time order form one stream; a gap of more than `max_gap_ms` (1,500 ms, the segmenter's own split) is a hard break; speaker-turn breaks are a variant the code supports (`PunctUnit::Turn`) because the diarizer flips labels mid-sentence near changes (WDER near changes 5 to 8 percent), so a per-turn window would add false periods. Default `PunctUnit::Stream`; the spike's S5 comparison may flip it (3.12).

Windows over a stream are the model's business: `apply.rs` has no tokenizer, so the `Punctuator` labels a whole stream (`label_stream`) and does its own windowing (at most `max_tokens` per window, `context_tokens` of context on each side whose labels are discarded, short streams batched with padding up to `batch` windows per run) in generic code under `punct/windows.rs`, parameterised by a token counter, so it is unit-tested with a fake tokenizer that counts whitespace tokens.

### 3.3 Applying labels: the invariants, in code

`crates/core/src/punct/apply.rs` is pure code (no model), unit-tested with a `FixturePunctuator` that returns scripted labels. It takes the ASR words of one stream and a `&mut dyn Punctuator`, and returns the words with display text set, plus a `PunctReport`.

Definitions. `old` is the ASR's text of a word. `base` is `old` under policy `KeepAsr`, and `old` minus its trailing allow-list marks under policy `Replace`. `new` is the display text.

1. Word count, order, `start_ms`, `end_ms`, `speaker`, `raw_label` and `confidence` never change. A result of the wrong length makes the whole stream keep its ASR text with `reason: "invariant"`; no panic in any build (the `JobQueue` catches job panics and would leave the meeting `processing`).
2. Per word, the only allowed changes from `base` are: one mark appended from the allow-list (3.4), one pre-mark prepended (`¿` `¡` only, Spanish), and letters raised from lower to upper case. A letter the ASR capitalised is never lowered. A letter is raised only when `to_uppercase` yields exactly one character whose lowercase is the original (so ß, ŉ and the Greek final sigma are left alone); for `tr` the letters i and ı are never raised (İ lowercases to two code points and the harness's normaliser would then split the word).
3. Per word, `echo::text::norm(new) == echo::text::norm(old)` must hold, and every character of `base` must appear in `new` in order with only case changes and allowed marks added. A word that fails keeps `old` and is counted in `rejected_words`. Checked at run time on every word.
4. `raw_text` is set to `old` only where `new` differs; otherwise it is `None` (stored NULL).
5. ASR marks: `KeepAsr` keeps a mark the ASR put on a word and lets the model fill the rest; `Replace` strips the ASR's trailing allow-list marks before labelling and uses the model's labels only. No mark is ever appended to a word that already ends in any punctuation character, or whose `norm` is empty. Default `KeepAsr`, because the ASR heard the prosody; S5 measures both and may flip it (3.12). A channel whose ASR already puts marks on 12 or more words per 100 (8 before section 3.13; Parakeet: 12.4) is not punctuated by the add-on at all, `reason: "asr_punctuates"`, and gets only the sentence-start casing rule; counted per channel.
6. Casing with a model that has no casing head: raise the first cased letter of a stream's first word and of every word after a sentence-final mark, in scripts with case (Latin, Cyrillic, Greek, Armenian). A stream starts at the channel's first word and after every gap break, so a segment that begins after a pause begins with a capital. Everything else keeps the ASR's casing. With a model that has casing labels (B, C): apply its flags as upgrades only, per character where the subword's normalised characters equal the word's lowercased characters, else first-letter only; then the sentence-start rule on top.
7. Marks predicted inside a word (B and C label subwords) are dropped and counted (`inner_marks_dropped`). For continuous scripts (zh, ja) marks go only at the ends of the runtime's word units.
8. The stream's last word gets the model's label like any other; nothing is forced.

The normalised word sequence of a run is therefore identical before and after punctuation, for the echo gate's `norm` and for the harness's `normalize_token` in both of its modes (the reviewer checked `tools/eval/common.py` 186 to 208: every allow-list mark is Unicode punctuation and is removed; an appended mark is never followed by a digit, so Whisper's decimal rule does not apply; apostrophes are untouched; `¿` and `¡` are removed). This implies identical cpWER, tcpWER and WDER. What does move: DER, JER and ORC-WER, because the hypothesis RTTM is built from segments and sentence ends plus a pause now split segments (3.5). The spike's S6 checks the same word-sequence property from Python.

### 3.5 Data model

- `words.raw_text TEXT` (nullable), migration `0004_raw_text.sql`: `ALTER TABLE words ADD COLUMN raw_text TEXT;`. NULL means "same as `text`". The store's backup-before-migration leaves `diarist.db.bak-3`; a beta.4 build refuses a version-4 database, so going back means restoring that copy (chunk H's checklist says so).
- `NewWord`, `TranscriptWord`, `Word` gain `raw_text: Option<String>` with `#[serde(default, skip_serializing_if = "Option::is_none")]` and `#[ts(optional)]`; `WORD_COLS`, `word_from_row`, `write_transcript`, `MemoryStore` and the store conformance suite follow. ts-rs regenerates `Word.ts` (committed).
- `words.text` holds the display text, because `regroup_segment` rebuilds `segments.text` from `words.text` on split, reassign and edit replay: a separate display column would need that rewritten, and storing labels instead of the raw text is lossy where the ASR already had a mark or a capital. `segments.text` stays `join_text` of the display words, so the UI, search snippets and exports need no change. `segments_fts` (`unicode61 remove_diacritics 2`) treats punctuation as separators and folds case, so search hits are unchanged; `MemoryStore`'s substring search is unaffected in practice.
- `engine_info.punctuation` on every run built after this chunk: `{applied, reason, model, revision, sha256, runtime: {name, version, path}, language, unit, policy, asr_marks_per_100: {mic, loopback}, words, marks_added, case_upgrades, rejected_words, inner_marks_dropped, marks_excluded, wall_s, threads}`. `runtime.path` is relative to the data root (no profile path in the database). `reason` is one of `ok`, `off` (setting), `no_model`, `language`, `asr_punctuates`, `runtime` (DLL missing, wrong module, missing dependency), `error` (with `message`), `invariant`.
- Eval harness: DER and JER come from the export RTTM's segment spans, which now end at sentence boundaries, so against cue-level Zoom references the new gaps read as missed speech; cpWER, tcpWER and WDER do not move. The eval data roots therefore set `transcript.punctuation = off` by default, so the accuracy tables keep measuring the speech model and the diarizer and stay comparable with the history; a config key `punctuation = true` in `configs.toml` turns it on for one config, enters the cache key, and is used once by chunk D for the S6 check through the app's own export and to record the DER and JER deltas beside the explanation.

### 3.6 Model packaging: description block, sidecar and manifest

The runner is generic; a description tells it what the model is. The same `PunctSpec` type comes from two places: the manifest entry for shipped models (`ModelEntry.punctuation`), copied by the scanner into the matched file's capabilities as it copies `file_right_context` today; and the `<file>.meet.json` sidecar (`models/classify.rs`, already read for every model file) for models a user drops in. No third file format.

- `PunctSpec`: `tokenizer` (relative path inside the model folder), `tokenizer_kind` (`hf_json` for `tokenizer.json`; a SentencePiece `sp.model` is converted once by the spike (S3) into `tokenizer.json`, so every shipped folder is `hf_json`), `input_casing` (`keep` or `lower`), `max_tokens`, `context_tokens`, `inputs` (names of the id and mask tensors), `heads` (a list: output tensor name, kind `post`, `pre`, `case` or `boundary`, `labels` in the output's order, `position` `last_token`, `first_token` or `per_subword`, `logits` or `decisions`), `marks_by_language` (optional overrides of 3.4), `casing` (`none`, `first_letter`, `per_char`). No floats (`Sidecar` derives `Eq`). Chunk B writes the exact schema into `docs/04-model-guide.md` section 5 and `manifests/punctuation-sidecar.example.json` after the spike's S3 and S4 have shown what A, B and C need.
- Scanner: an `.onnx` is a `punctuation` file only when a parsed `PunctSpec` exists for it (sidecar or matched manifest entry) and validates at scan time (the tokenizer file exists in the folder, `heads` is not empty); otherwise it stays `unknown` with the note "needs a `.meet.json` that describes its labels", and the rule at scan.rs 289 to 291 (an unknown-classified file takes its manifest entry's role) does not apply to the punctuation role, so a partial download is never a selectable model. `ensure_selections` adds `ModelRole::Punctuation` and does not accept an unknown-role file for it; `recommended()` needs no change (ranks 0, 1, 2 already work); `views::ModelSelection` gains `punctuation`; the CLI's `parse_role` gains `punctuation`.
- `ModelEntry` gains `files: Vec<ModelExtraFile>` (`{path, url, size_bytes, sha256}`; `path` is a relative subpath inside the folder, validated: no `..`, no absolute, because `models.user.json` is user-writable, and Hugging Face names are nested, `onnx/model_quantized.onnx` with `tokenizer.json` at the root), `dir: Option<String>` (the folder under `models\` a direct entry lands in; default `user`), `punctuation: Option<PunctSpec>`, all `skip_serializing_if` so the round-trip tests stay meaningful. `file`, `url`, `sha256` keep describing the primary file; `size_bytes` becomes the total of all files (it feeds `disk_needed_bytes`). `DownloadItem` gains a `files` list so the setup screen and Settings can show every file's URL and hash for Copy link and manual install (docs/00: a browser plus a file copy always works).
- Download order: the extra files first, the primary file last, so the scanner (keyed on the primary file) never sees a selectable model whose tokenizer is missing. One core function, `models::fetch::fetch_entry(entry, paths, progress)`, used by the desktop `pull_model` and the CLI `models pull`.
- Dropping a Hugging Face folder in by hand works once the user adds the sidecar; docs/04 section 5 gets the example. This keeps the "user owns the folders" principle: a model the app has never heard of is a folder plus one small JSON.

### 3.7 ONNX Runtime: packaging and loading

- Crate: `ort = "=2.0.0-rc.15"`, `default-features = false`, `features = ["std", "load-dynamic", "api-31"]`. `api-31` is named explicitly: with `default-features = false` the API baseline would fall to 17 and System32's 1.17 would load instead of failing. With `api-31`, an older library makes `OrtGetApiBase()->GetApi(31)` return null and `ort` fails at init with its own message. `download-binaries` and `copy-dylibs` stay off (no build-time fetch). rc.15 fixes over 30 instances of undefined behaviour against rc.13 and needs Rust 1.92: the workspace `rust-version` moves to `1.92` (Tauri 2.12 needs 1.90; the toolchain here is 1.99; CI builds on stable; `.cargo/config.toml`'s MSRV fallback keeps working). Chunk B reports the `cargo update` diff that the bump causes. If rc.15's `Session::run` takes `&mut self`, `Punctuator::label_stream` takes `&mut self` too.
- Tokeniser: `tokenizers = "0.23"` with `default-features = false, features = ["onig"]` (the C build is accepted; rusqlite already builds C; `fancy-regex` is the pure-Rust alternative S3 can validate). Parallel encoding is turned off inside the post-pass. The 34 MB `tokenizer.json` costs about a second to load and over 100 MB of RSS; it counts toward the budget below.
- The DLL is not bundled in the installer and is not a separate download kind. It travels as one of the punctuation model entry's `files`, re-hosted on the project's models release (ONNX Runtime is MIT; its `LICENSE` and `ThirdPartyNotices.txt` travel beside it), and is installed in the model's folder under the name `diarist-onnxruntime.dll`. The rename is the simplest defence against the Windows loader resolving an import of `onnxruntime.dll` by name to another copy already in the process; nothing in the CPU execution provider imports the DLL by its own name. (The first draft had a `components.json` and a component download kind under `engine\`; the review's alternative removes a manifest file, a download kind and its UI. A user who wants one DLL for several drop-in models can put it under `engine\onnxruntime-<version>\`, which the loader searches second; `engine_dirs` only takes folders with `bin\nemo-speech.exe`, so that folder is ignored by the engine scan.) The installer stays at 7 MB; the exe grows by the `ort` and `tokenizers` code (2 to 4 MB).
- Loading: `ort::init_from(<absolute path>)` before any other `ort` call, once per process (ort's environment is global, so the first DLL loaded is the one for the session; a model change to a folder with another DLL version takes effect after a restart, and Settings says so). Then two checks before any session is created: (a) module identity: `GetModuleHandleExW(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS | UNCHANGED_REFCOUNT, <the ort API function pointer>)` then `GetModuleFileNameW` must give our path (not `GetModuleHandleW("onnxruntime.dll")`: a full-path load of a different file is a second module, and the by-name lookup could return another copy, so the first draft's check would have reported false failures); (b) the loaded library's version string (`OrtApiBase::GetVersionString`) must start with the entry's `runtime_version`. Either failing: no punctuation, `reason: "runtime"`, one log line with both paths, and a Diagnostics row "Punctuation runtime". If ORT ever crashes the app in-process (plan 11's crash capture would show it), punctuation moves to a worker process in the next release; not built now.
- Dependencies of the DLL: chunk B runs `dumpbin /dependents` on it. If it imports `MSVCP140.dll` or `VCRUNTIME140_1.dll`, chunk B checks what `nemo-speech.exe` imports too; if the engine already needs the same redistributable, every working install has it and nothing changes; otherwise `punct::current` probes the dependency with `LoadLibraryW` from the system directory and, when missing, returns `reason: "runtime"` with the DLL's name and Diagnostics links to Microsoft's redistributable page (no automatic install). Note that `libloading`'s `LoadLibraryExW(path, 0)` does not search the DLL's own folder for its dependencies.
- Execution provider: CPU only. No DirectML (in sustained engineering), no CUDA EP (149 to 239 MB, and the GPU is busy with the ASR in the post-pass).
- Session: created per job and dropped after it (RAM back to baseline; the bulk action keeps one session for its whole run), `intra_threads` from `transcript.punctuation_threads` (default 4, clamped to 1 to `available_parallelism`), `inter_threads` 1, graph optimisation level 3. Decision rule from S7: the default becomes the smallest thread count whose seconds per hour of audio, measured while another GPU transcription runs, is within 1.5 times the fastest measured; 4 if S7 does not run that variant. S7 measures Python ORT, not the shipped Rust path, so chunk B's CLI check re-reads the 15 s per hour and 0.8 GB bars from `wall_s` and RSS on the same clip.
- Memory budget: at most 0.8 GB peak RSS during the job, tokenizer included (A int8: 0.4 to 0.6 GB estimated for the model). B ships only as int8 if it wins (fp32 would be 1.4 to 1.8 GB).

### 3.9 Older meetings and every other rebuild

One helper, `punct::rebuild_run(store, paths, meeting, why) -> RebuildReport`, on the pattern of `restore_echo_dropped`, used by "Add punctuation", "Remove punctuation", the bulk action and the CLI (not by the promoted live run, 3.2):

1. Refuse while the meeting records or is processing (`check_idle`).
2. Find the root run: the current run, following `punctuation.rebuilt_from` and `echo.restored_from` to the run they were built from, so Add, Remove, Add again never chain copies of copies.
3. Read the current run's words by channel, with the engine's labels, from `raw_text.unwrap_or(text)`: every rebuild starts from the ASR's text, so switching punctuation off, changing the model or restoring echo words all go through the same path.
4. Punctuate every channel with the current selection and setting (or strip, when the setting is `off` or `why` is `remove`).
5. `build_transcript_channels` with the run's segment options (`engine_info.segmentation`, else the defaults); a new run of the same kind as the current one; `engine_info` copied from the current run with `punctuation` replaced and `punctuation.rebuilt_from = <root run id>`; the current run's `echo_dropped` and `engine_info.echo` copied (Restore and the details list read `echo_dropped` of the current run; without the copy every rebuilt run would lose Restore); speakers carried by identity (6); `set_current_run`. Nothing is deleted: the earlier copy stays as docs/02 says, and the earlier copy's badge in the run list says what it was.
6. Identity carry, new on `RunStore` (`carry_over_identity(from, to)`, both stores, a conformance case): the word set and labels of a rebuilt run are the source's, so speaker rows are copied by `(channel, engine_label)` with name, colour, `global_id`, `merged_into`, `needs_review` and the name anchors, then `reassign` edits are replayed. The time-overlap `carry_over` (10 s region minimum) would give small speakers "new label" badges and lose their colours on every rebuild, and the bulk action would spread that across every older meeting. Restore switches to the identity carry too (its words are the source's plus the restored `me` words).
7. `live_run_of` (live/mod.rs 1235), `rerun_post_pass` and `recover` skip runs with `punctuation.rebuilt_from`, as they skip `echo.restored_from`. And the post-pass carries names over from the newest current run that descends from `job.live_run` (following `rebuilt_from` and `restored_from`), else from `job.live_run`, and computes `unplaced_names` from the same run, so names given on a copy survive a re-run (today they do not, for restored copies either; tests.rs 2114 to 2126 is updated with the new rule).

Callers: Restore (which adds the dropped words before step 4); the meeting page action "Add punctuation" (shown when the current run has no `punctuation.applied == true` and a model is installed) and "Remove punctuation"; a bulk action in Settings, "Add punctuation to N older meetings", whose confirmation says the shown transcript changes on N meetings and the earlier runs stay, and which queues one `rebuild_run` job per meeting through the `JobQueue` (CPU only, seconds each, cancellable, one ORT session for the whole batch); `diarist-cli punctuate <meeting> | --all-missing`. Restore stays a direct command (it is today) and may take a few seconds longer on a long meeting; Add, Remove and the bulk action run as jobs with progress.

Default for older meetings: offered, never automatic. The owner has not decided; the per-meeting action and the bulk action cost one click each and leave the old runs in place, so the decision can be taken later without data loss. If the owner wants it automatic, a startup sweep over meetings without `punctuation.applied` becomes a setting (`transcript.punctuation_backfill`), default off, in a later release.

### 3.10 Casing with B or C

The ASR's own casing (about 6 percent of words: "I", some names) is the floor. A model's casing labels only raise case (3.3 rule 6). Where the model says lower and the ASR says upper, the ASR wins. Where the model says UPPER for an acronym and the subword's characters match the word's, the whole word is upper-cased; where SentencePiece's normalisation changed the character count, only the first letter is raised. The `<ACRONYM>` label of B and C (which inserts periods inside a word) is never applied. German nouns and names come only from B or C's casing head; the spike's rule 4 (3.12) decides whether that is worth the bigger model.

#### 3.13.3 A scoring defect the report must carry: Zoom's ellipses are never scored

Found by the Opus reviewer. The Zoom references end 626 words (gate set) and 818 (talks) with `...`, 21 to 23 percent of their period-class marks. The harness's `normalize_token("word...")` yields the pieces `("word", ".")`; the stray `.` never aligns, so the reference's mark is dropped and the word is scored as if Zoom had written nothing: any mark a model writes there counts as a false positive. The report's method says "`…` counts as `.`", but that is not the right correction either: Zoom capitalises the word after `...` only 36 percent of the time (1,313 cases over the 13 sessions), against 94 percent after `.` and 4 percent after `,`, so about two thirds of its ellipses are mid-sentence trail-offs. A Zoom ellipsis is neither a confirmed sentence end nor a confirmed "none", so the fair scoring leaves those words out, with the capitalisation split as a check (an ellipsis before a capital scored as `.`, the rest left out). Re-scores of the S6 punctuated transcripts (A, B-q8pc, C on Aug 2 and Talk 1; pure alignment, no model run; the adjudicator's `scratchpad/rescore_ellipsis.py` and the reviewer's own scorer agree), pooled micro / boundary F1:

| As spiked (scored as "none") | 0.583 / 0.705 | 0.585 / 0.644 | 0.588 / 0.625 |
| Left out (primary) | 0.588 / 0.713 | 0.594 / 0.659 | 0.598 / 0.641 |
| `.` before a capital, else left out (check) | 0.576 / 0.680 | 0.585 / 0.641 | 0.589 / 0.624 |

4. Speech-pass wall time within 10 percent, peak VRAM on the 77-minute file within 150 MB (the weights grow 67.5 MiB).
5. Tag agreement with the standalone diarizer within 0.1 points, and the speaker counts unchanged.

And at least one of these shows a gain:

6. Fewer gaps summed over the set with fewer reference words inside them, or at least one gap of 5 s or more of the shipped file that the fixed file does not have; or
7. The EN model's FLEURS English WER (21.5 today, nearly all deletions on quiet speech) falls by 3 points or more; or
8. Mean cpWER over the set improves by 0.3 points or more.

#### 12.2.2 Fix 1: the owner's level, and the transfer guard without it

The bug. `CalibrationStats::owner_db()` (layers.rs 398 to 408) is the median level of the words in no text run spoken while the far end was silent, from at least 20 of them (`OWNER_MIN_WORDS`); with fewer, the median of all words in no text run (the `unmatched` fallback). After the canceller, on a recording where the far end talks nearly all the time and the owner is silent, the words in no run are garbled residue, so the fallback measures the residue: meeting 21's −50.19 dBFS. The transfer guard (transfer.rs 186 to 189, `MARGIN_DB` 12) then asks a candidate to sit under −62.19 dBFS, below the cancelled mic's own floor (−61.38), and blocks 1,989 of 1,993. The reviewer found the quiet branch is not safe either: on meeting 21 the kept words with the far end silent number 16 (11 to 16 with the mapping moved ±200 ms), 15 of them with no live word within 300 ms (residue stamped after the far end stopped), and residue accrues in such windows at about 0.3 words per minute, so a talk of about 65 minutes would reach 20 quiet residue words and the quiet branch would read the residue too. The estimate must exclude residue by what residue is, not by when it fell.

Design (one estimator, one guard rule, one plausibility check):

1. **After the canceller, the owner's level is estimated from words the canceller left alone**: words in no text run, spoken while the far end was silent, cut by under 3 dB (`presence.attenuation_db < transfer::ATTENUATION_DB`; the eval's "clean owner" class), 20 or more; with fewer, any word in no run cut by under 3 dB (this keeps the case the old fallback got right, an owner who talks only over the far end); with fewer than 20 of those, unknown. ### 12.3 D8: repetition loops

The signature, measured on the stored final transcripts of meetings 12 to 21 (counts and times only). Nemotron stamps word starts on an 80 ms grid (one encoder frame) and a word lasts 80 ms at the median; distinct consecutive words share a start frame 1.6 to 2.3 percent of the time and are one frame apart 14 to 18 percent. Runs of 6 or more identical normalised tokens: 17 runs, median start-to-start gap 0 ms at the 10th, 50th and 90th percentile (a loop comes out in bursts of up to 9 tokens in one frame, 160 to 320 ms between bursts). Runs of 4 or 5: 35, gap p10 0 / p50 240 / p90 320 ms. Runs of 3: 112, gap p10 120 / p50 280 / p90 560 ms. Of the 52 runs of 4 or more, 27 have a median gap of at most 80 ms, 6 lie at 81 to 160 ms and 19 over 160 ms (repeats at human pace: a stutter, laughter, "no no no no"). Pairs: 837, 108 with a gap of at most 80 ms. The decoder's loops therefore have a timing signature that real repeats do not, and the rule uses it rather than the count alone (the analysis's "4 or more" would also remove 81 words at human pace, 67 on the far end and 14 in "me").

Decision: collapse on the transcript side, both channels, behind a setting, measured by the eval gate. Not "do nothing" (the loops are the most visible of the errors the owner named, 251 to 254 words on these meetings, 145 on meeting 12, and the respin does not remove them: section 10 of the analysis); not display-only (`regroup_segment` rebuilds `segments.text` from `words.text`, so hiding needs a per-word flag and a UI; and search would still find the loop); not Nemotron 3.5 for English files (D4's rule is not met: 3.5 has 4 percent fewer differences on the far end by Whisper's judgement, which favours a model with Whisper's habits, and more on the owner's own speech, 358 against 338; its 4 loops / 18 words against EN's 19 / 129 are what the collapse removes anyway; the leaderboard and its own card favour EN).

The rule (`crates/core/src/transcript/loops.rs`, pure code, unit-tested): over one channel's words in time order, a run is a maximal sequence of consecutive words with the same normalised text (`echo::text::norm`) and the same speaker label, split wherever consecutive starts are more than `LOOP_SPLIT_MS` (400) apart (5 of the 33 fast runs have an internal gap over 400 ms, one of 1.68 s; one word spanning that pause would hide it from the segmenter). A piece is collapsed when it has 4 or more words with a median start-to-start gap of at most `LOOP_FRAME_MS` (80), or exactly 3 words that all start in the same frame (one-frame spacing is within the base rate for distinct words, so 3 at 80 ms is not a signature; 4 of the 7 such triples qualify). The piece becomes its first word with `end_ms` of the last and the last word's trailing ASR mark; `start_ms`, `speaker`, `raw_label` and `confidence` of the first are kept. Never collapsed: pairs; runs at human pace; an empty `norm`; digit-only tokens; Han, Kana and Thai (continuous scripts, where grammatical triples are common and the runtime's word units are large). Expected on meetings 12 to 21: about 250 words (254 over the channel stream by the reviewer's count, 251 per segment by the planner's), 3 runs crossing a segment boundary, 0 crossing a speaker label, 4 of them false starts of the next word.
