# 0.1.0-beta.2: accuracy, languages, icon, crash capture

Status: proposed 16 Oct 2026, planner Fable 5.1, implementation Opus 5.5 agents. Replaces the "next" order in the handoff for one release: the items here are what a stranger installing Diarist from the website hits in the first ten minutes, and what the site can claim with numbers behind it. The rest of the hardening plan (`docs/plans/11-hardening.md`: bench, soak, CLI in the installer) follows in beta.3.

Every quality-affecting chunk ships only with a before-and-after table from `tools/eval` on the fixed set (`docs/05-eval-data.md`); nothing regresses any session beyond the noise band and nothing changes the live path without a latency number.

## 1. Findings that set the plan (16 Oct 2026)

The installed runtime (NeMo-Speech.cpp 0.2.0, `nemo-speech help transcribe` and `share/doc/nemo-speech/docs/asr/configuration.md`) exposes three accuracy levers Diarist does not use, and the app lets a user choose a language the selected model cannot transcribe.

### C. Languages

Goal: a user who picks a language gets a model that can transcribe it, or one click to install it; the list only offers what works, with the quality tier visible.

Behaviour:

- The language list is built from a static tier table (section 1) intersected with the selected ASR model's `capabilities.languages` (the GGUF header lists them; `classify.rs`). Transcription-ready languages are listed plainly; broad-coverage ones carry "(reduced accuracy)"; adaptation-ready ones are not listed. `auto` stays, with its one-line note about the first second, and is never the default. A model with no language list (Parakeet, user GGUFs) shows the full list marked "not checked for this model" and never triggers a switch. Spanish and Portuguese are listed per locale (es-ES, es-US, pt-BR, pt-PT), and the tag passed to the runtime is the one it honours (`ja-JP`, `zh-CN`, `vi-VN`; bare `ja`/`zh` run as auto). Stored settings and old meetings' languages are mapped when used.
- Choosing a language the selected model does not cover: if an installed ASR model covers it (by capability, not by manifest name), the job (import or recording) runs on it automatically, the stored selection unchanged, with the same notice pattern as the low-VRAM switch; if none does, the sheet shows "Install Nemotron 3.5 (742 MB)" with the existing download path, and the job does not start on the wrong model. Live: the server is restarted with the matching model when the sheet's language changes and a server with another model is idle (not at Start: readiness takes 3 to 6 s and the feed buffers 10 s).

- First run: `default_language` is seeded once from the system language (the WebView's `navigator.language`, mapped to the tier table, else `en`), and the Setup screen has a one-select language step that picks the recommended ASR model (EN model for English, Nemotron 3.5 otherwise).

## 5. Decisions and open questions

- **Punctuation route** (revised after the review). The runtime's PnC hook stays as plumbing, because a self-converted GGUF from NVIDIA's NGC checkpoints cannot be redistributed and would be a maintenance trap across runtime versions (the converter's layout is not a contract; nobody re-pins our file; a PnC load failure fails the whole import), and because the runtime may skip the hook for Nemotron 3.5, which it treats as self-punctuating. The shipped punctuation model is therefore the 47-language XLM-RoBERTa model (Apache-2.0, a pure per-token classifier that preserves words and word times): first through the hook if the runtime's converter accepts the Apache-2.0 NeMo checkpoint (A tries it), else in beta.3 through `ort` with `load-dynamic` and the ONNX runtime downloaded as a component (installer stays under 10 MB), the model quantised to int8 (about 300 MB) and hosted by this project, case upgrades only (never lowercase what the ASR capitalised), a scanner rule for an `.onnx` plus `sp.model` folder. A Parakeet dual pass is rejected: it drops speech, peaks at 4.6 GB, is file-only and needs an alignment of two hypotheses 0.3 s apart.
- **Language gating.** Automatic switch with a notice (the low-VRAM pattern) rather than a blocking dialog: the product principle is that nobody fights the app. By capability, never by manifest name, so a hand-dropped or re-converted model counts.
- **Which languages to verify first.** The spike covers de, es, fr, it, pt, hi, ja. The owner may name others; the tier table says what to expect.
- **Lookahead for live.** Kept at the low-latency setting in beta.2; a 560 ms setting is worth a latency measurement later, since the live bar is 1.5 s and first text today arrives in about 0.2 s.
